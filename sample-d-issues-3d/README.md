# sample-d：指摘事項 拡張デモ②（実 Issue＋要素情報の自動付与＋詳細・編集＋3D 表示）

Forma（ACC）の実 Issue を Issues API で取得し、ピン先の要素情報をモデルから自動付与して表示するデモです。

- **Issue 一覧**：列はユーザー側で設定可能（「列の設定」）。Forma の Issue 項目（ID／タイトル／ステータス／期日／作成日／担当者／公開／コメント／添付）に加え、**モデルから読んだ要素プロパティが自動で列として追加**されます（階・位置・タイプ名・材質など、モデルごとに実在するキーを集計）。表示件数はデフォルト10件、最大100件まで同時表示できます。検索・ステータス絞り込み・並び替え対応。
- **Issue 詳細**：行クリックで詳細パネルが開きます。Forma のスナップショット画像（Issue の `snapshotUrn` から署名付き S3 URL 経由で取得。無い場合はモデルのサムネイルで代替）、自動付与された要素情報の一覧、ピン先ビューなどを表示します。
- **編集**：詳細パネルからタイトル／ステータス／期日／説明を編集し、Issues API（PATCH）で実 Issue に保存できます。ステータスの選択肢は Issue ごとの `permittedStatuses`（許可された遷移）に従います。
- **3D 表示**：ビューアへの表示は専用ボタン（行の「3D」ボタン／詳細の「ビューアで表示」）から行います。APS Viewer がモデルを SVF 逐次配信で読み込み、対象要素だけを残して他をゴースト表示にし、対象を赤く点滅させ、ピン位置に青いピンを立てます（壁の向こうや地中の対象でも見えます）。Issue のピン先に応じてモデルは自動で切り替わります。

## 対象モデル（5モデル対応）

| モデル | 規模 | 備考 |
|---|---|---|
| DACHsampleproject.rvt | RVT 132MB | 建築（木造・鉄骨・RC 混在） |
| Snowdon Towers Sample Structural.rvt | RVT 約32MB | 構造（軽量） |
| Snowdon Towers Sample Architectural.rvt | RVT 約95MB | 建築 |
| Snowdon Towers Sample Facades.rvt | RVT 約53MB | ファサード |
| sample_architecture.rvt | RVT 約63MB | 建築（日本語モデル）。変換ジョブは API から投入済み |

## 実行方法

```bash
node server.mjs   # http://localhost:3000
```

依存パッケージはありません（`npm install` 不要）。`.env`（APS_CLIENT_ID / APS_CLIENT_SECRET）と `.token.json`（3-legged トークン）がこのフォルダに必要です。

⚠️ `.token.json` の refresh token はローテーション式（使うたびに新しいものへ差し替わる）です。**更新したら必ずファイルへ書き戻す**こと。書き戻さずに再利用するとチェーン全体が失効し、再ログイン（sample-a の login-manual）が必要になります。サーバーは起動時に読み込むため、外部でトークンを更新したらサーバーも再起動してください。

## 仕組み

- サーバーの API：`/api/issues`（実 Issue の取得＋要素情報の付与）、`/api/index-status`（索引の構築状態だけを返す軽い確認用）、`/api/token`（Viewer 用 2-legged トークン。サーバー側でキャッシュ）、`/api/thumbnail`（モデルのサムネイル）、`/api/snapshot`（Issue のスナップショット画像）、`/api/issues/update`（実 Issue の PATCH 中継）。画面のスクリプトは `public/app.js` に分離しています。
- 要素情報の付与：Issue のピン（linkedDocuments）の externalId を、変換データ同梱のプロパティ DB（model.sdb）の対応表で Viewer の dbId に読み替え、要素のプロパティ（要素名・階・通り芯など）を引きます。Model Derivative の objectid と Viewer の dbId は一致しないため、この読み替えが要ります。
- 索引は**事前生成せず、サーバー起動後に Model Derivative API から非同期に構築**します（プロパティ一式の取得＋model.sdb のダウンロードと解析）。サーバーは索引の完成を待たずに起動し、画面にはモデルごとに「構築中」が表示され、できあがったモデルから順に要素情報が付与されます。構築結果は `cache/` に派生キャッシュとして残り、次回起動時は即座に使われます（モデルのバージョンが変わっていたら自動で作り直し）。コールドスタートからの構築は実測で1モデルあたり3〜6秒でした。
- スナップショットの取得：旧 OSS 直 GET は廃止（403 "Legacy endpoint is deprecated"）のため、`signeds3download` で署名付き S3 URL を得てから取得します。なお署名 URL の有効期限は約2分と短い点に注意。

## モデルの追加方法

`data/models.json` に1件追加してサーバーを再起動するだけです（索引は起動後に API から自動で構築されます）。viewableGuid は Model Derivative の metadata（3D ビュー一覧）から選びます。なお索引の中身をファイルとして確認したい場合の単体ツール `extract-model.mjs` は、アプリ本体とは分離して `sample-d-dev-tools`（開発・検証用ツール置き場）に置いています（サーバーの動作には不要）。

変換ジョブの投入が必要なファイルでは、エンドポイントに注意してください。正しくは **`POST /modelderivative/v2/designdata/job`**（URN はボディに入れる）。`POST /modelderivative/v2/designdata/{urn}/job` は存在せず 404 になります。ACC ハブのファイルでは `x-ads-derivative-scopes` ヘッダ（`b360project.*`、`O2tenant.*`。値はバージョンの derivatives リンクから取得）が必要な場合があります。

## ビューア切り替えと OBJ 抽出表示（v8.9）
- ビューア左上の小さなボタンで「APS Viewer」と「OBJ」を切り替えられる（選択は localStorage に保存）。
- OBJ モードでは、選択した Issue の対象要素＋周辺をサーバーが Model Derivative の OBJ ジョブ（objectIds 指定）で切り出し、three.js の軽量ビューアで表示する（対象は赤、周辺はグレー）。APS Viewer 側の処理は従来どおり。
- 周辺の抽出は簡易版：隣接する通り芯（Column Location Mark）を最優先し、同タイプ・同じ階（Level／Reference Level／Base Level／Base Constraint）で補う（最大48件）。
- サーバー API：`GET /api/extract?issue=<Issue ID>`（ジョブ投入→manifest ポーリング→OBJ ダウンロード→内容照合。結果は要素集合単位でディスクキャッシュ）。
- 実測の対応状況：Snowdon 3モデルは抽出成功（構造 49件／建築 29件など）。DACH と sample_architecture は OBJ 変換自体が「No Geometries to extract」で失敗する（ファイル固有。Data Exchange の処理エラーと同じファイル）。その場合は画面にエラーを表示する。

### v8.9.2 の修正（ちらつき再発と初回読み込み）

- **「Rendering...」のちらつき再発への対処**：対象要素の赤点滅を「最初の数回（約4.5秒）だけ点滅し、最後は濃い赤で停止」に変更しました。点滅のたびに画面全体の再描画が走るため、無限に続けると大きなモデルを遠景で見ている間、再描画が終わらず「Rendering...」表示とちらつきが続くためです。
- **カメラのフィットは1回だけ**：形状の読み込み完了後、対象ごとに1回だけフィットします。読み込み途中のイベントで繰り返しフィットすると、不完全な範囲へのフィット（モデル全体の俯瞰）と競合して画面が跳ぶためです。3D ボタン／ツールバーのフォーカスボタンを押した場合は、明示操作としてもう一度フィットします。
- **OBJ ビューアの遅延読み込み**：three.js は OBJ モードに切り替えた時点で初めて読み込むようにしました（従来はページ表示時に常時読み込み）。初回表示が軽くなります。

### v8.9.3 の修正（ピン消失のバグ修正と点滅の代替）

- **一覧モードでピン（ラベル・引き出し線）が表示されなくなったバグを修正**：部材ボックス取得のフォールバック判定で `box.isEmpty`（メソッド参照）と書くべきところの誤りのため、ボックスが常に「取得失敗」になり、全 Issue のラベルが描かれていませんでした（`box.isEmpty()` が正）。以前はピン座標へのフォールバックがこの不具合を隠していて、v8.9.1 でフォールバックを外したことで表面化しました。
- **赤点滅を廃止し、代替ハイライトに変更**：色替え点滅は再描画負荷が高いため、対象要素は濃い赤で一度だけ塗り、位置の合図は画面上の CSS ピン（波紋アニメーション、3D 描画に触らない）で出すようにしました。
- ゴースト透明度の適用は、値が変わった時だけマテリアル書き換えと再描画を行うようにしました（ロードイベントでの重複適用で描き直さない）。

### v8.10 の修正（ラベル消失の真因・透明化・カメラ・読み込み表示）

- **ラベル／引き出し線／フォーカスピンが表示されなかった真因を修正**：`InstanceTree.getNodeBox(dbId, out)` の out は THREE.Box3 ではなく `[minx, miny, minz, maxx, maxy, maxz]` の数値配列でした（LMV 本体のソースで確認）。Box3 を渡していたため常に「ボックスなし」になり、全 Issue のアンカーが取得できていませんでした。配列形式に修正し、予備としてフラグメント境界の合成も追加。
- **ゴースト表示を廃止し、本物の透明化に変更**：対象外のフラグメントのマテリアルを「元の材質のまま透明にした複製」に差し替えます（`FragmentList.setMaterial`）。色・質感は元のまま薄くなるので、部材が重なる箇所でもエッジが単色で重なる見づらさがありません。スライダは「まわりの部材の透明度」に改称（0%＝透明化オフ）。
- **カメラを「引き」に**：標準の fitToView は部材が画面いっぱいで近すぎたため、部材ボックスから距離を計算し、余裕を持たせて収めるようにしました。
- **読み込み表示を実状態に連動**：ビューアの「読み込んでいます」は静的な文言で、実際には読み込んでいない時にも出ていました（データ到着前に初期化が終わるとモデル読み込みが始まらない競合もあり）。データ読み込み中→モデル読み込み中（進捗％）→完了で消える、という実状態連動にし、競合も修正。Issue 表はデータ到着までスケルトン UI を表示します。

### v8.11 の修正（透明化の方式変更・ラベル/カメラの隠れバグ・読み込み中UX）

- **透明化の方式を変更**：クローン材質への差し替えでは、LMV の MaterialManager が GPU 材質を使い回して opacity の変更が描画に反映されませんでした（後述のローカル Viewer リグで実測）。元の材質そのものの transparent / opacity / depthWrite を書き換える方式に変更（LMV 自身のフェード実装もこの方式）。対象が周囲と材質を共有する場合は、対象のフラグメントだけ専用材質に付け替えて保護します。あわせて、透明化中と逐次配信中はエッジ（輪郭線）表示を切ります（輪郭線は不透明なまま残り「線の檻」に見えるため）。
- **隠れバグ2件を修正**：`Autodesk.Viewing.Math` という名前空間は LMV 7.99 に存在せず（実測）、使っていた3箇所（ラベルの位置合わせ、フォーカスピン、引きカメラ）が例外で黙って死んでいました。LMV が公開する THREE に置き換え。これでラベル表示と「引き」のカメラが初めて実際に動きます。
- **読み込み中の UX**：読み込み表示がビューア全面を覆ってマウス入力を塞いでいたため、上部のピル型表示に変え入力を通すようにしました。カメラはツリー到着時点で対象へ先に寄せます（逐次配信はカメラに近い部材から優先的に届くため、対象周辺が先に実体化します）。
- **ローカル Viewer リグを構築**（`~/workspace/forma-hands-on/vm-viewer/`）：モデル一式（SVF バブル）を fetch 経由でダウンロードし、Viewer 本体とワーカーもローカルに置くことで、この VM のブラウザでも Viewer が実際に描画できるようになりました。今後の Viewer 挙動の検証に使えます（プロパティ DB のツリーだけはローカルでは構築されません）。

### v8.12 の修正（一覧モード既定 ON・透明化の反映キック）

- **「指摘事項一覧をモデルに表示」を既定で ON** にしました。モデル読み込み完了と同時に一覧モード（ステータス色＋ラベル＋周囲の透明化）に入ります。ツールバーのボタンで従来どおり切り替えできます。
- **透明化が画面に反映されない問題の修正**：LMV は材質プロパティを変更しただけでは描画リストを作り直さず、カメラを動かすまで画面が古いままになることをローカルリグで実測しました。材質変更の直後に、同じ位置・注視点で setView する「再描画キック」を入れて即時反映させます（スライダ操作にもデバウンスして適用）。透明化処理の例外はステータス欄に表示するようにし、黙って失敗しないようにしました。

### v8.13 の修正（透明化の作り直し：同期・一括・clone なし）

- 実機で「描画が変」（大きなパステル色の塊と黒い破片、スライダ 0% でも残る）という報告を受け、透明化の実装を作り直しました。原因は、従来の「非同期チャンク適用＋対象材質の clone 保護」が、読み込み直後のスライダ操作や復元処理と競合し、書き換え途中の材質（transparent のまま・depthWrite オフ等）が残って描画順が壊れたことと判断しました。
- 適用・復元を**同期的に一括**で行い、再入の余地をなくしました。材質の clone は廃止し、「対象以外が使う材質」だけを書き換えます（対象だけが使う材質は自動的に保護され、共有材質は対象も一緒に薄くなりますが、対象はテーマカラーで識別できます）。ローカルリグで適用→復元の往復後に全材質が元の値へ正確に戻ることを確認済みです。

### v8.14 の変更（透明化を廃止し「対象の手前だけ消す」方式へ）

- 目的を再定義（ユーザー）：奥にある部材・部材の間にある部材を見えるようにすること。方式は全体透明化ではなく、**カメラと対象の間にある部材だけを特定して Viewer 標準の非表示（hide）で消す**方式に作り替えました。材質には一切触らないため、透明化で頻発した描画の不安定さが起きません。
- 判定方法：カメラから「対象ボックスを拡大した8隅＋中心」へ引いた線分と交わる要素を手前とみなします。対象自身・その親子要素・他の Issue 要素は消しません。スライダは「消す範囲」（対象ボックスの拡大率、0% でオフ）。カメラを動かすと見通しが追随して再計算します。
- あわせて初期表示のモデルを選択中の Issue のモデルに合わせました（従来は先頭モデル固定で、選択と表示が食い違って見えました）。

### v8.15 の変更（ラベルを画面周囲へ散らす配置）

- 一覧モードのラベル配置を、対象の直上から**画面周囲のマージン帯**へ変更しました（ユーザー仕様）。中央の「青エリア」（左右 12.5%・上 18%・下 26% の内側）にはラベルを置かず、中心点から指摘箇所を通る放射線が青エリアの境界を出る位置にラベルを置き、引き出し線で結びます。
- 中心点は動的：X は画面中央固定、Y は表示中の指摘箇所の 2D 座標の重心。同じ辺に集まったラベルは、辺に沿ってずらして重なりを解きます。

### v8.16 の修正（フォーカスとラベル消失）

- **フォーカスボタン**：押すと一覧モードが解除されてしまう／カメラが動かない問題を修正。一覧は維持したまま、その場で対象へフィットし、見通し（手前消去）を再計算するようにしました。あわせて選択時の処理でも、カメラのフィットを手前消去より先に行い、応答を速くしました。
- **近づくとラベルが消える問題**：原因は2つ。(1) 手前消去で Issue 要素の「親」要素を消すと配下の Issue 要素ごと隠れていた → 全 Issue 要素の祖先も消去対象から除外。(2) ラベルの表示判定に要素の非表示状態を使っていた → 判定は「中心かボックスの隅がカメラの前にあるか」だけにし、中心がカメラの後ろでも隅が前にあればラベルを出すようにしました。
- 手前消去の候補（要素ボックス一覧）をモデル単位でキャッシュし、再計算は幾何判定だけに高速化しました。

### v8.17 の修正（ラベルの表示条件・重なり・フォーカスの傾き）

- **画面外の指摘はラベルも出さない**：指摘箇所（中心またはボックスの隅）の投影点が画面内にある場合だけ、ラベル・引き出し線・ドットを表示します。
- **ラベル同士は被らない**：同じ辺の詰め込みを前後両方向から繰り返す方式に作り替え、間隔の維持を画面端への収まりより優先しました。辺をまたぐ隅の衝突も全体チェックで逃がします。
- **フォーカスでビューが斜めになる**：フィット時にカメラの上方向を現在のカメラから引き継ぎ、`setView` へ明示的に渡すようにしました。

### v8.18 の追加（Issue 表の列ソート）

### v8.24 の修正（描画中に非表示を触らない：ロード遅延とちらつきの対策）

実機報告「ロードがめっちゃ遅くなった」「モデルを動かす度に Rendering が走ってちらつく」への対応。原因は、手前の部材の非表示を維持するための2つの仕掛けが、描画（プログレッシブレンダリング）の最中に `viewer.hide()` を繰り返し呼んでいたことでした。可視性を変えると描画はやり直しになるため、読み込みが終わらず、操作のたびに描画が再開してちらついていました。この2つは v8.19 で入れた「ストリーミングすり抜け」仮説の対策で、その仮説自体は v8.20 の調査で誤りと判明していたものです。

- 撤去1：読み込み進捗イベントのたびに非表示セットを再主張する処理（最大で毎秒2回 hide を呼んでいた）。
- 撤去2：適用の1.2秒後・3.5秒後に再計算する追いかけタイマ。

### v8.21 の改善（ちらつき対策＋フォーカスの滑らかな移動）

実機報告「モデルを動かしたり Issue を切り替えると描画がちらつく」と「フォーカス移動を滑らかに」への対応。

- **ちらつきの原因（コード上で特定）**：(1) ラベル配置の計算がカメラ移動のたびに全ラベル分の `offsetWidth` 読み取り（強制リフロー）付きで走っていた。(2) 手前消去の再計算が毎回「旧セットを全部表示→新セットを全部非表示」の組み替えだった。(3) Issue 切替のたびにマーカー DOM を全再構築していた。
- **対策**：(1) ラベルサイズは構築時に測って保持し、配置は `transform` のみで書き換え。カメラ変化のハンドラは描画フレーム単位に間引き（rAF 合体）、display の書き込みは変化時のみ。(2) 非表示セットは差分だけを適用（変わらない再計算では Viewer を一切触らない。単体テスト済み）。(3) マーカーはモデル＋ステータスが同じなら再構築を省略。
- **フォーカスの滑らかな移動**：`setView` は瞬間移動のため、現在位置から目的地までイージング（easeInOutCubic）付きで補間するアニメーションにした。所要時間は移動距離に応じて 0.65〜1.2 秒。移動中にユーザーがビューアを操作したら即座に譲る（中断をリグで実測）。OS の「視差効果を減らす」設定時は瞬間移動に戻す。ピボットは移動開始時に対象中心へ合わせる。

### v8.20 の修正（原因を実測で確定：手前消去の例外とフォーカスの回転中心）

実機で直っていない2件について、仮説のパッチではなく実測で原因を確定してから直しました。

- **手前消去が効かない（真因）**：v8.16 で入れた「Issue 要素の祖先を消去対象から除外する」処理が、LMV に存在しないメソッド `tree.getNodeParent(...)` を呼んでいました（正しくは `getNodeParentId`）。例外で `computeOccluders` 全体が毎回死ぬため、`viewer.hide()` に一度も到達していませんでした。安全な `addAncestors` ヘルパー（例外・循環・深さのガード付き）に置き換えました。なお判定ロジック自体は DACH の実形状データでオフライン検証済みで、各カメラ位置で遮蔽要素 26〜31 件（敷地全体に広がる大きな塊の要素を含む）を正しく検出します。v8.19 の「後から届いた部材がすり抜ける」対策（再計算・再主張）は無害なので残していますが、本件の原因ではありませんでした。
- **フォーカスでビューが斜めになる（真因）**：ローカルリグで実測したところ、`setView` はカメラの回転中心（ピボット）を動かさず、モデルの原点に残したままになります。そのため回転操作が原点中心になり、ビューが斜めに振れていました。あわせて、フォーカスの移動方向が「その時のカメラ方向」を引き継ぐため、全体表示の急な斜め方向が近接ビューにも残っていました。対策：フォーカス時にピボットを対象の中心へ合わせ、方向は方位だけを引き継いで仰角を 28° に固定、上方向はワールド Z に固定しました。

### v8.19 の修正（手前消去が効かない問題）
