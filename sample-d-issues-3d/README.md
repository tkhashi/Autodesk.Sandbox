# sample-d-issues-3d — 指摘事項 拡張デモ② 対象箇所＋周辺の3D表示（①Viewer方式／③部分切り出し方式）

Forma（旧ACC）の指摘事項（Issues）拡張のデモ第2弾。要望「指摘事項を選ぶと、該当箇所と周辺の3Dが下に表示される。部分データだけ読めば高速なはず」を、2つの実装方式で比較できるようにしたもの。

## 方式の比較

| | ① APS Viewer 方式 | ③ 部分切り出し方式 |
|---|---|---|
| データ | モデル全体の変換データ（SVF）をクラウドから逐次配信 | 対象＋周辺のジオメトリだけを切り出した GLB |
| 表示 | Viewer で対象＋周辺を分離表示（isolate）＋カメラフィット | three.js で GLB を読むだけ |
| 転送量（実測・ISSUE-003） | モデル全体寄り | **139 KB**（対象34KB＋周辺105KB） |
| 表示まで（実測） | 初回読み込みに数秒〜（モデル全体の読込） | **103〜345 ms** |
| 範囲外の要素 | そのまま広げて見られる | 含まれない |

対象モデルは Forma 実環境のサンプルプロジェクト Snowdon Towers の構造モデル。Issue はデモ用データ6件（sample-c と同一、ピンは必ず要素前提）。

## 動かし方

1. このフォルダに `.env` を置く（sample-a と同じ `APS_CLIENT_ID` / `APS_CLIENT_SECRET`）。①のトークン発行に使う
2. `node server.mjs`（依存パッケージなし、Node 標準機能のみ）
3. ブラウザで `http://localhost:3000` を開き、Issue をクリックして左右のパネルを比べる

③だけなら `public/index.html` を静的に開いても動作する（①はトークン発行のためサーバー必須）。

## 実装メモ

- **要素IDの対応付け**：Issue の要素は Model Derivative プロパティの objectid で引くが、SVF2 の変換データ側の dbId とは一致しない。変換データ同梱のプロパティDB（model.sdb）の `_objects_id` テーブルが externalId 経由で両者を結ぶ。①の isolate も③の切り出しも、この変換側 dbId を使う
- **「周辺」の定義（デモ仕様）**：対象要素のバウンディングボックスを水平±10ft／上下±6ft 広げ、交差する要素を近い順に最大60件
- **③の切り出し**：`tools/extract-subsets.mjs`（svf-utils の glTF 変換に dbId フィルタを指定し、対象／周辺を別々に書き出して GLB 化）。本番では起票時の Webhook を起点に裏側で実行する想定で、このデモでは事前に切り出し済みのものを同梱している
- ①の Viewer 本体は Autodesk CDN から読み込む

## 検証状況（2026-11-15）

- ③：ローカル環境で全 Issue の表示を確認。表示 103〜345ms、転送 139KB〜3.16MB（要素数14〜61件）
- ①：トークン発行エンドポイントと Viewer 初期化・分離表示のコードは実装済み。ただし構築用 VM のブラウザからは Autodesk CDN への接続がトンネルエラーで通らず、実描画の確認はできていない（通常のブラウザ環境では動作する想定）。手元の環境で `node server.mjs` から確認できる
